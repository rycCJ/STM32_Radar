# 数据与命令协议

## 运行时命令

全部命令采用ASCII、LF结尾（`\n`），921600、8N1，无流控。新增MODE与LINK选择均为RAM状态，不增加Flash写入。

| 命令 | 端点及回应 |
| --- | --- |
| `AT+LINK=DIRECT` | 中控串口1；回复同名行，结束转发、复位停止雷达、释放PA2/PC3 |
| `AT+LINK=BRIDGE` | 中控串口1；回复同名行，取得雷达控制权，之后其他命令转发到雷达 |
| `AT+LINK?` | 中控串口1；返回当前LINK行 |
| `AT+STATUS?` | 中控串口1；返回 `AT+STATUS=雷达队列溢出,主机队列溢出,UART错误`，计数自中控启动累计 |
| `AT` | 雷达配置状态回复 `AT+OK`；工作状态收到任意字节会触发复位 |
| `AT+MODE=ADC` | 配置状态选择新封装的单路ADC输出，回复同名行 |
| `AT+MODE=IQ` | 配置状态选择新封装的150点复数距离数据，回复同名行 |
| `AT+MODE=POINT` | 配置状态选择新封装的原点云包，回复同名行 |
| `AT+MODE=LEGACY` | 配置状态选择原IQ+点云组合包，回复同名行 |
| `AT+START` | 开始采集；显式使用MODE后先回复 `AT+STARTED`，随后输出数据 |

非法MODE返回 `AT+ERROR=MODE`。MODE必须在配置状态设置；工作中直接发送整条MODE只会先触发复位。工具先通过AT获得明确应答，再设置MODE，不把第一次发送成功等同于执行成功。

保留旧 `AT+PROG=01/02` 与旧参数命令。未显式使用MODE时，旧ADC和旧组合输出维持原格式。MODE=LEGACY将当前RAM功能选为02；之后旧PROG仍可改变原功能选择。配置初始化中已有的Flash值被默认参数覆盖问题另见问题清单。

## RDR1版本1帧

新增ADC/IQ/POINT模式使用48字节定长头、payload和4字节CRC。所有整数及float32均小端；不直接发送C结构体，无编译器填充依赖。

| 偏移 | 字节 | 含义 |
| --- | --- | --- |
| 0 | 4 | ASCII `RDR1` |
| 4 | 1 | 版本1 |
| 5 | 1 | 类型：1 ADC、2 IQ、3 POINT |
| 6 | 2 | 头长度48 |
| 8 | 4 | payload字节数 |
| 12 | 4 | 帧序号，从0开始，每发送一帧递增 |
| 16 | 8 | 本帧采集开始前读取的RTC计数 |
| 24 | 4 | RTC时钟Hz，即运行时 `lrc_clk` |
| 28 | 2 | 样本/距离单元/点的数量 |
| 30 | 2 | Chirp索引：ADC缓存起始0，IQ为2，POINT为65535（不适用） |
| 32 | 2 | 通道槽：ADC缓存起始0，IQ为6，POINT为65535；不是已确认物理天线号 |
| 34 | 1 | 样本类型：1 int16、2两个float32平面、3原点云包 |
| 35 | 1 | bit0表示选择模式后的首帧；其余位0 |
| 36 | 4 | 当前有效ADC采样率10000000Hz，非帧率 |
| 40 | 4 | IQ距离单元间距，float32米；其他模式0 |
| 44 | 4 | 保留，0 |
| 48 | N | payload |
| 48+N | 4 | CRC-32/ISO-HDLC，小端 |

CRC使用反射多项式 `0xEDB88320`，初值和最终异或均为 `0xFFFFFFFF`，覆盖偏移4到payload末尾，不包含magic与CRC本身，与Python `zlib.crc32` 一致。

- ADC：512个小端int16，1024字节；只是当前缓存起始数据，不是完整多天线多Chirp立方体。
- IQ：先150个float32实部，再150个float32虚部，共1200字节。
- POINT：payload就是原点云包，共 `12+9×点数` 字节，包含其原帧头与长度。

RTC来自设备的低频RC时钟，频率字段表示当前软件所用频率，不代表经外部仪器校准。时间戳表示整帧启动前读取时刻，不是串口发送时刻，也不是所选Chirp的精确触发时刻。跨复位不拼接为一条连续时间轴；解码器通过首帧标志、序号和时间回退记录会话变化。

## 兼容格式

- 原ADC：`01 02 03 04 05 06 07 08` 加1024字节采样，共1032字节，无设备时间和CRC。
- 原IQ块：`66 BB` 加600字节实部、600字节虚部，再 `BB 66`，共1204字节。
- 原组合：一个IQ块后紧接一个点云包。
- 原点云：`55 AA`、u32长度L、u16帧间隔ms、u8 numTLV=1、u8 type=1、u16点数，再每点9字节；L=`6+9×点数`，整包L+6。每点依次为u16距离索引、u8速度索引、u8方位索引、u8俯仰索引、4字节强度。

兼容模式没有新增CRC、绝对设备时间或帧序号，统计能力因此不同。原点云中的帧间隔不是包序号；原ADC的200ms等待也不能用来假设精确均匀采样。
