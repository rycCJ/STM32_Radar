# 已知问题与本轮边界

以下问题来自原代码或尚未完成的硬件核验，不在结构整理提交中修改算法行为。

1. 雷达编译保留3个原警告：tempR/tempI未使用，以及switch分支越过变量初始化。未借重构调整该处理链。
2. ParamConfigInit先读Flash和计算分辨率，再调用Default_Param_Config覆盖多项RAM参数。旧Flash写入命令保留，但重启后参数是否实际生效不能仅凭写入成功判断。新模式元信息单独按当前带宽计算IQ距离间距，不修改原算法参数。
3. 原ADC只导出缓存起始512点，含200ms固定等待。原数据没有设备时间；新增ADC时间戳解决记录来源问题，不提高采样频率或保证呼吸心跳分析适用性。
4. IQ原实现取j=2、槽m=6，未核实其物理天线对应关系；不存在已实现的跨Chirp平均。编译配置为16位ADC、抽取2，本轮不支持随意更改这些宏后继续沿用同一协议元信息。
5. 原中控点云逻辑没有完整帧长度/点数边界防护，且用uint16接收32位长度。它保留在ControllerLegacy路径供对照，生产转发链路不调用它；新增观察器使用长度上限和新帧CRC，不把不完整数据当点数。
6. 为支持新命令，新增协议入口同时对原雷达命令接收数组增加长度限制和LF完成处理，避免超长输入覆盖内存；该变化属于采集扩展提交，不混在行为保持的拆分提交中。旧命令要求LF，CRLF不是本轮约定。
7. 同板电气隔离仅能通过实际测量确认。默认PA2/PC3为输入高阻，不主动复位；板上RSTN偏置、启动稳定性、直连与转发接法仍需验收。
8. 双串口同为921600且无流控。16KB队列能吸收短时延迟，但不是无限缓存；队列溢出/UART错误在会话中记录，不能据编译结果宣称长期无丢帧。
9. 新封装、CRC及转发会增加少量传输/处理时间。本轮不改固定等待、波形或运算流程，真实帧间隔应从设备时间测量。
10. 结构已拆分，但原硬件寄存器状态机仍集中在App_Func.c中，内部共享变量暂留Radar_Internal.h。下一轮可在硬件回归后进一步收敛，避免本轮为消除全局量而扩大时序变化。
